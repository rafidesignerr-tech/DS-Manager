# D.S Hub

A web portal for browsing a design system and coordinating the team that maintains it. Built from the D.S Hub BRD as a **reusable template**: the structure, roles and workflows are complete, and all reference content is clearly marked sample content you replace later.

- **Public:** Home, Foundations, Components (grid, list and Atomic view), Icons, Product Kit (coming soon), Changelog, Feedback.
- **Team workspace:** Tasks (list and board), task detail with comments and activity history, Notifications, Profile.
- **Managers:** Team (invite, roles, suspend), Feedback inbox (triage, internal notes), Changelog entries (draft, publish).

## Stack

| Layer | Choice |
|---|---|
| UI | Align UI v1.2 components and tokens (Tailwind CSS v4.1 CSS-first, Radix UI, tailwind-variants, Remix Icon, Inter) |
| Framework | React Router v8 (framework mode), TypeScript, server-side loaders and actions |
| Hosting | Cloudflare Workers |
| Database | Cloudflare D1 with Drizzle ORM |
| Files | Cloudflare R2 (profile images) |
| Auth | Better Auth (email + password, sessions, password reset) |
| Validation | Zod |
| Tests | Vitest (domain rules), an HTTP end-to-end suite (`tests/e2e.mjs`) |

Optional services: Resend for email (password reset, invitations) and Cloudflare Turnstile for the public feedback form. Both are off until you add their keys.

## Project layout

```
app/
  config/hub.ts          Product name, atomic taxonomy, policy flags for open BRD decisions
  domain/                Pure rules: permission matrix, task lifecycle, notification recipients, feedback schema
  server/                D1 schema, auth, and one module per area (tasks, team, feedback, changelog, reference)
  components/ui/         Align UI components (button, form, display, overlay, page, feedback, time)
  components/            App components (shell, task badges, catalog toolbar, pickers)
  routes/                One file per page; every loader/action checks permissions on the server
  app.css                Align UI token sheet (generated by the Align UI CLI) + small additions
drizzle/                 SQL migrations and the sample seed
scripts/                 Sample seed generator
tests/e2e.mjs            End-to-end role checks
```

## Run locally

Requires Node 22.22+.

```bash
npm install
cp .dev.vars.example .dev.vars        # then set BETTER_AUTH_SECRET to a long random string
npm run db:migrate:local
npm run db:seed:local                 # optional: neutral sample content
npm run dev                           # http://localhost:5173
```

Open `/setup` to create the first manager. That page only works while no account exists. Everyone else joins by invitation from **Team**.

Without `RESEND_API_KEY`, emails (invitations, password resets) are printed to the dev server console so you can open the links.

Checks:

```bash
npm run typecheck
npm test                              # domain rules
npm run preview                       # production build, then in another terminal:
node tests/e2e.mjs path/to/preview.log   # needs a fresh DB with the /setup manager (manager@example.com / sample-password-1)
```

## Deploy to Cloudflare

You need a Cloudflare account. The Workers Paid plan is recommended: password hashing needs more CPU time per request than the free plan allows.

1. **Sign in to Wrangler**
   ```bash
   npx wrangler login
   ```
2. **Create the database and bucket**
   ```bash
   npx wrangler d1 create ds-hub-db
   npx wrangler r2 bucket create ds-hub-media
   ```
   Copy the `database_id` printed by the first command into `wrangler.jsonc`.
3. **Set your URL and sender** in `wrangler.jsonc` → `vars`: `PUBLIC_BASE_URL` (for example `https://ds-hub.<your-subdomain>.workers.dev`, or your own domain) and `EMAIL_FROM`.
4. **Add secrets**
   ```bash
   npx wrangler secret put BETTER_AUTH_SECRET      # long random string
   npx wrangler secret put RESEND_API_KEY          # optional, for real email
   npx wrangler secret put TURNSTILE_SITE_KEY      # optional
   npx wrangler secret put TURNSTILE_SECRET_KEY    # optional
   ```
5. **Create the tables**
   ```bash
   npm run db:migrate:remote
   ```
   To load the sample content as well: `npx wrangler d1 execute ds-hub-db --remote --file=./drizzle/seed/sample.sql`.
6. **Deploy**
   ```bash
   npm run deploy
   ```
7. Open `<your URL>/setup`, create the first manager, then invite the team from **Team**.

Custom domain: add it under the Worker's **Settings → Domains & Routes** in the Cloudflare dashboard, then update `PUBLIC_BASE_URL` and redeploy.

## Replacing sample content

All sample rows have `is_sample = 1` and show a **Sample** badge. Remove them with:

```sql
DELETE FROM reference_item WHERE is_sample = 1;
```

Group labels (Foundations groups, component and icon categories) live in `reference_group`. The atomic levels and reference statuses are configured in `app/config/hub.ts`.

## Security notes

- Every loader and action checks the permission matrix on the server (`requirePermission`); hidden buttons are only a convenience.
- Public sign-up is closed at the HTTP layer. Accounts come from `/setup` (first manager only) or invitations.
- Passwords are hashed by Better Auth and never read by app code. Invitation tokens are stored as SHA-256 hashes.
- Suspending a member ends their sessions immediately.
- Profile images are checked by file signature (PNG, JPG, WebP), capped at 2 MB, and served only to signed-in members.
- Feedback is private, has a honeypot and optional Turnstile, and duplicate submissions are ignored.
- Session cookies are `SameSite=Lax` and `Secure` on HTTPS.
